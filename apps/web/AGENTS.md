# Tevion Frontend Agent Instructions

## Scope

`apps/web/` is the Tevion frontend application and interaction prototype.
The frontend owns the user-facing Explore/Refine workbench, browser state,
API client, authentication UI, candidate presentation, feedback controls, and
frontend-only verification.

## Allowed paths

A frontend Issue may modify only:

- `apps/web/**`
- frontend-specific documentation under `docs/` when the Issue explicitly asks
  for documentation changes

## Forbidden paths

A frontend Agent must not modify:

- `apps/api/**`
- `apps/api/migrations/**`
- `infra/**`
- `docker-compose.yml`
- backend configuration or secrets

If a backend capability is missing, document the API contract needed and create
or link a backend Issue. Do not implement the backend as part of a frontend
Issue.

## Integration exception

Only an Issue explicitly labeled `area:integration` may modify both
`apps/web/**` and `apps/api/**`. Such an Issue must state the API contract,
user outcome, non-goals, and end-to-end verification steps.

## Product boundaries

- Preserve the Explore → Generate → Select → Feedback → Refine direction.
- Keep the first visual goal explicitly adult male; "youthful" means adult
  freshness and vitality, never minors or childlike ambiguity.
- Do not expose private images, tokens, or user preferences in logs,
  screenshots, commits, or Issue comments.
- Keep frontend state and API errors inspectable and user-readable.

## Verification

For static prototype changes:

- Run a JavaScript syntax check with Node when available.
- Verify all referenced DOM IDs exist.
- Open or serve `apps/web/index.html` and run the interaction verification page
  when the change affects browser behavior.
- Report exact commands and actual outcomes.

For API integration changes:

- Verify the exact endpoint, method, request body, authentication header, and
  response shape against the backend contract.
- Do not invent unavailable endpoints; report the missing backend contract.

## Git rules

- Use the repository Issue branch format: `agent/issue-<number>-<short-slug>`.
- Use conventional commits.
- Do not merge, force-push, or delete branches automatically.
- Keep frontend and backend changes separated unless the Issue explicitly
  requires an integration slice.

## Current prototype

This directory was migrated from the private prototype at
`/Users/adtiger/Tevion-frontend`. Keep the prototype dependency-free until UX
validation justifies a Vite/React migration.

The external directory is retained as a backup during migration and must not
be modified by frontend automation unless explicitly requested.

## Current API base

The prototype currently targets `http://127.0.0.1:8010/api/v1`. Keep this
configurable in future work; do not add secrets or hard-code production tokens.

## Completion report

Every frontend worker must report:

- files changed;
- API assumptions;
- verification commands and actual results;
- known missing backend capabilities;
- branch name and commit if created;
- final status: `FRONTEND_COMPLETE`, `INTEGRATION_REQUIRED`, or
  `FRONTEND_FAILED`.

Never claim a browser flow or API call succeeded without executing it.
